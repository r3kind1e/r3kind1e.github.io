**普通用户运行一个带 SUID 位的程序时，这个程序可以临时以“文件所有者”的权限运行；如果文件所有者是 root，那么程序执行过程中可能拥有 root 权限。**

## 1. 先理解普通 Linux 权限

例如：

```bash
ls -l /usr/bin/passwd
```

你可能会看到：

```text
-rwsr-xr-x 1 root root 68248 /usr/bin/passwd
```

正常权限通常是：

```text
-rwxr-xr-x
```

但这里变成了：

```text
-rwsr-xr-x
```

注意：

```text
s
```

出现在文件所有者的执行权限位置。

这就是 **SUID = Set User ID**。

而且这个文件：

```text
owner = root
```

所以普通用户执行 `/usr/bin/passwd` 时，程序可以临时获得 root 的有效权限。

---

## 2. 为什么 Linux 需要 SUID？

最典型的例子就是：

```bash
passwd
```

普通用户：

```text
kali
```

当然没有权限直接修改：

```text
/etc/shadow
```

因为：

```bash
ls -l /etc/shadow
```

通常类似：

```text
-rw-r----- 1 root shadow ...
```

但你又必须能够修改自己的密码。

所以系统设计成：

```text
用户
 ↓
执行 passwd
 ↓
passwd 带 root SUID
 ↓
passwd 临时拥有 root 权限
 ↓
修改 /etc/shadow
```

这本身不是漏洞。

关键在于：

> **SUID 程序是否能够被滥用。**

---

# 3. Real UID 和 Effective UID

这是理解 SUID 最重要的概念之一。

假设用户：

```text
kali
```

UID：

```text
1000
```

执行一个 root-owned SUID 程序。

此时进程可能是：

```text
Real UID:       1000
Effective UID:  0
```

Real UID：

```text
真正启动程序的人是谁
```

Effective UID：

```text
程序当前按照谁的权限运行
```

所以：

```text
RUID = kali
EUID = root
```

Linux 在进行很多权限检查时看的是 **Effective UID**。

这就是为什么 SUID 可以产生提权机会。

# 4. 渗透测试里第一步：找 SUID 文件

CTF / TryHackMe 里非常经典：

```bash
find / -perm -4000 -type f 2>/dev/null
```

含义：

```text
find /
```

从根目录开始找。

```text
-perm -4000
```

找带 SUID bit 的文件。

```text
-type f
```

只找普通文件。

```text
2>/dev/null
```

隐藏 Permission denied 之类的错误。

你可能得到：

```text
/usr/bin/passwd
/usr/bin/sudo
/usr/bin/chsh
/usr/bin/newgrp
/usr/bin/mount
/usr/local/bin/something
```

看到这些之后，不是说：

> “有 SUID，所以可以提权。”

而是要问：

> **这里有没有“不应该拥有 SUID”的程序？**

---

# 5. 系统自带 SUID ≠ 漏洞

比如：

```text
/usr/bin/passwd
/usr/bin/chsh
/usr/bin/su
/usr/bin/mount
```

看到它们不用立刻兴奋。

因为很多 Linux 系统本来就有这些。

真正值得注意的通常是：

```text
/usr/bin/python
/usr/bin/bash
/usr/bin/vim
/usr/bin/find
/usr/bin/nmap
/usr/local/bin/customapp
```

尤其是一些：

```text
自定义程序
```

比如：

```text
/usr/local/bin/backup
/opt/scripts/tool
/home/admin/check
```

如果：

```bash
ls -l /usr/local/bin/backup
```

发现：

```text
-rwsr-xr-x 1 root root ...
```

就非常值得调查。

---

# 6. 为什么某些 SUID 程序可以提权？

假设管理员错误地给某个工具加了 SUID：

```text
-rwsr-xr-x root root /usr/bin/someprogram
```

如果这个程序本身提供了：

```text
执行命令
打开 shell
调用编辑器
执行外部程序
加载插件
调用脚本
```

之类的能力，那么就可能出现：

```text
普通用户
 ↓
运行 SUID 程序
 ↓
程序 EUID = root
 ↓
程序调用 shell / command
 ↓
shell 继承权限
 ↓
root
```

所以问题其实不是：

```text
SUID = 漏洞
```

而是：

```text
SUID
+
危险程序功能
+
错误配置
=
提权
```

# 8. SUID 提权不只是“直接弹 shell”

这里是新手很容易误解的地方。

SUID 漏洞其实有很多类型。

### 类型 A：程序本身能执行 shell

最直接：

```text
SUID binary
 ↓
执行 shell
 ↓
继承 root EUID
```

---

### 类型 B：PATH 劫持

比如某个 root SUID 程序内部写了：

```c
system("service apache2 restart");
```

而不是：

```c
system("/usr/sbin/service apache2 restart");
```

它依赖：

```text
PATH
```

寻找 `service`。

如果攻击者能够控制 PATH，就可能让程序运行一个不同的 `service`。

思路：

```text
SUID root program
 ↓
调用 "something"
 ↓
Linux 根据 PATH 找 something
 ↓
攻击者控制搜索路径
 ↓
执行攻击者控制的程序
```

这就是 **PATH Hijacking**。

THM Easy 靶机特别喜欢考这个。

---

### 类型 C：调用可修改的脚本

比如：

```text
root SUID binary
 ↓
执行
/opt/scripts/backup.sh
```

如果：

```bash
ls -l /opt/scripts/backup.sh
```

发现普通用户能修改：

```text
-rwxrwxrwx
```

那么就很危险。

因为：

```text
你修改 script
 ↓
root SUID binary 执行 script
 ↓
script 以高权限运行
```

---

### 类型 D：不安全的环境变量

程序可能依赖：

```text
PATH
LD_PRELOAD
LD_LIBRARY_PATH
```

等环境变量。

不过 Linux 对 SUID 程序有很多保护措施，所以 `LD_PRELOAD` 等并不是看到就能随便利用。

---

### 类型 E：程序本身存在漏洞

例如自定义 SUID 程序：

```text
buffer overflow
command injection
arbitrary file write
```

因为程序运行时：

```text
EUID = 0
```

原本普通的漏洞就可能升级成：

```text
Local Privilege Escalation
```

---

# 9. THM 中我建议你的枚举流程

以后进一台 Linux 靶机，拿到 low-priv shell 后，可以形成这个肌肉记忆：

```bash
id
```

先看：

```text
我是谁
属于哪些组
```

然后：

```bash
sudo -l
```

检查 sudo 权限。

然后：

```bash
find / -perm -4000 -type f 2>/dev/null
```

检查 SUID。

接下来对异常二进制：

```bash
ls -la /path/to/binary
file /path/to/binary
```

必要的时候：

```bash
strings /path/to/binary
```

如果是自定义程序：

```bash
strings /usr/local/bin/backup
```

可能直接看到：

```text
tar
cp
cat
service
backup.sh
```

然后你就开始思考：

```text
它是不是调用了外部程序？
有没有写绝对路径？
调用的文件我能不能改？
环境变量能不能控制？
```

这就已经从：

> “背提权命令”

进步到：

> **理解 privilege escalation 的原理。**

## 10. 你可以这样记

给你一个非常简化的模型：

```text
                  Linux SUID

普通用户
   │
   │ execute
   ▼
┌─────────────────┐
│ SUID executable │
│ owner = root    │
└────────┬────────┘
         │
         ▼
RUID = user
EUID = root
         │
         ▼
程序执行高权限操作
         │
         ├── 安全设计 → 正常功能
         │
         └── 可被滥用 → Privilege Escalation
```

所以以后看到：

```text
-rwsr-xr-x root root
```

你脑子里马上应该出现：

> **这个程序运行的时候 EUID 可能是 root。它有没有办法让我利用它的功能执行我想执行的高权限操作？**

这就是 SUID 提权最核心的思维。

对于你现在恢复 eJPT 手感的阶段，我建议尤其把 **`sudo -l`、SUID、cron、writable files/PATH、Linux capabilities** 这五类 Linux 本地提权先重新熟悉起来；THM Easy 里面出现频率非常高。
